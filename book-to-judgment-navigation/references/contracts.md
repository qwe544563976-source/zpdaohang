# 冻结原文原子判断导航合同

## 1. 流程位置

| 环节 | 输入 | 当前环节负责什么 | 输出 | 不能做什么 |
|---|---|---|---|---|
| 上游正式书包 | 已验收的书籍文字和原文原子 | 证明文字、切卡和原文原子已经通过上游闸门 | `accepted-package.json` | 不由本流程修改 |
| 整书知识地图 | 已验收书包或只读试验夹具和读取范围 | 建章节、主题、术语和原文位置地图 | `references/knowledge/` | 不判断现实问题 |
| 判断方法蒸馏 | 知识地图、原文原子、事实名称 | 建方法骨架、逐步骤证据、依赖和停止条件 | `methods/`和方法配方 | 不直接发布候选 |
| 判断导航总装 | 允许执行的方法 | 生成问题类型、必查事实、四路查询和停止条件 | `references/navigation/` | 不制造书中规则 |
| RAG（原文证据检索系统） | 查询计划 | 重新取回真实原文原子和相邻原文 | 可引用原文 | 不判断当前事实是否满足 |
| 判断代理 | 原文条件和当前事实 | 分成满足、未满足和未知 | 有条件结论或停止 | 不凭单一配置套结论 |

## 2. 工作单合同

目标目录必须有 `WORK_ORDER.json`，并且只能选择一种输入模式：

- `PILOT_TEMP（临时测试夹具）`：允许读取工作单中锁定的测试原文原子，必须同时有 `PILOT_STATUS.json`，永远禁止发布和迁移。
- `FORMAL（正式书包）`：只允许提供 `accepted-package.json`绝对路径，拒绝裸原文原子路径。

工作单至少明确：

- 工作名称和操作类型；
- `pilot_only（仅供试验）`与`publishable（允许正式发布）`；
- `artifact_scope（产物身份）`；
- 试验夹具的原文原子绝对路径和内容摘要，或正式已验收书包绝对路径；
- 书籍和版本的人类可读身份；
- 允许读取的章节编号或原文原子编号；
- 目标目录；
- 是否允许修改 RAG、排盘系统、OCR 和原文原子；
- 试验输入的大小、最后修改时间和内容摘要；
- 本轮验收要求。

试验任务必须为 `pilot_only = true`、`publishable = false`、`formal_migration = FORBIDDEN`。正式任务必须为 `artifact_scope = FORMAL`且`pilot_only = false`。输入路径不存在、范围为空或保护开关不符合要求时停止。

## 3. 正式书包与原文原子只读合同

正式模式的 `accepted-package.json（已验收书包凭证）`至少必须提供：

```text
schema_version = accepted-package/v1
package_id
artifact_scope = FORMAL
distillation_allowed = true
book.book_id
book.edition_id
book.source_artifact_id
evidence_atoms.path
evidence_atoms.content_sha256
evidence_atoms.contract_version
upstream_gates.source_text_bidirectional = pass
upstream_gates.chunking_validation = pass
upstream_gates.accepted = pass
```

任何上游闸门未通过、内容摘要不一致或书籍版本身份缺失时停止。蒸馏窗口不修正式书包。

### 3.2 正式书包检查失败时的分流

正式书包的实时检查失败后，先看失败原因，不把所有失败都当成同一种事情：

1. **数据或身份失败**：原文内容、页数、表格、边界、编号、版本身份或内容摘要对不上。按 P0 处理，停止这本书所有依赖原文的下游工作。
2. **只缺记录或登记字段**：上游独立复核已经证明正文、表格和原文原子没有问题，只是报告里少了逐页记录。按 P1/P2 处理，正式书包仍然不能算通过，但蒸馏窗口可以继续做不绑定正式证据的工作：候选来源分组、专题排序、固定考题、JH8／RAG 接口联调和模板检查。

凭证未齐期间禁止生成或更新正式方法配方、逐字短引、PDF 页码绑定、正式查询路线和可发布文件。候选工作只能使用已有的 `canonical_ref_id（规划定位号）`，不能把它当原文证据编号交给 RAG 或最终回答。正式书包通过后，必须重新读取新版原文，再从头绑定 `evidence_atom_id`；不能把候选定位号直接换成正式编号。

“只是记录缺失”必须由上游复核证据说明，蒸馏窗口不能自己把权威验包失败改判成 P1/P2。

### 3.3 开工前必须证明原页结构没有漏登记

“已经登记的表格都能找到”不能证明“原书没有漏掉表格”。正式书包的上游检查必须同时证明以下事项；A 类（原书有稳定编号）和 B 类（原书没有稳定编号）都不能跳过：

1. 从原 PDF 逐页查看实际存在的表格和其他必须保留的结构单元，每一页都要有人工确认记录；确认是 0 的页面也要有查看依据，禁止脚本批量盲填 0。
2. 原页人工清点总数与 `pages.jsonl（逐页正文和页码表）`中的已登记结构总数双向对账。漏登记、重复登记、损坏登记和明确排除项必须分别列出，不能只检查已登记块是否存在。
3. 跨页续表必须回指唯一、真实的前后页表格块；只有“续自某页”文字，或回指普通正文／标题，不算关系成立。
4. 已登记表格还要检查正文是否足以保存原表结构和内容。只有一个表格块编号、但正文已经损坏或只剩极短乱码，仍按 P0 失败。

蒸馏窗口不重新打开 PDF 做这项普查，也不修改 `book.md`、`pages.jsonl`或原文原子；它在每个正式方法批次开工前，只读检查当前工作单绑定的那一本书：

```bash
python -c "from pathlib import Path; from tools.register_accepted_package import run_authoritative_validation; run_authoritative_validation(Path(r'<当前工作单的 accepted_package_path>'))"
```

退出码不是 0 时，本批不得读取正式原文生产方法。`python tools/register_accepted_package.py --check`仍用于查看全部已登记书包和项目总状态，但不能让另一册书的失败连坐当前书。只有上游提供证据证明“正文和结构完整、仅缺登记文件”时，才按第 3.2 节继续不绑定正式证据的准备工作。

上游验证器的固定错误回归至少保留两组已复现样本：Destiny 第 34、50、78～79 页的坏表／漏表／续表断链，以及 UK 第 2、11、15、17、74、118、120、154 页的非零表格页和续表关系。它们用于证明上游闸门能抓到同类错误，不要求每本新书复制这些页。

蒸馏流程只消费工作单范围内的原文原子。每个被引用原文原子至少要有：

```text
evidence_atom_id
chapter_number
chapter_title
heading_path
content_role
exact_text
pdf_pages
citation
```

`content_role=case（完整案例正文）`是合法原文原子，可以进入整书知识地图和搜索路线。它可以带 `evidence_assets（证物附件数组）`；当前附件只允许 `asset_role=chart_crop（星盘裁图）`。附件由上游正式书包验证，蒸馏侧只读，不把星盘裁图、模型转写的 YAML、摘要或解释改写成第二份正式正文。

以下字段原样读取，不得改写：

```text
evidence_atom_id
exact_text
pdf_pages
citation
```

所有知识地图、方法和主题中的原文锚点只能写 `evidence_atom_id`或`evidence_atom_ids`。`work_id`、`parent_id`、`card_id`、`source_atom_ids`、`filters.work_ids`和`contract_v2.1`属于退役接口，禁止映射、兼容或重新写入新产物。

缺字段、边界异常、编号异常、页码异常或引用异常时，在 `UPSTREAM_ISSUES.json`记录问题编号、原文编号、影响、阻塞步骤、状态和受影响方法，并报告主窗口。`UPSTREAM_ISSUES.md`只能由机器记录生成。不得读取 PDF、整本正文或逐页正文生成替代原子。

问题先于方法发现时，`affected_method_ids（受影响方法列表）`允许暂时为空。只有开放且 `blocking = true` 的 P0 问题，才由验证器按真实引用和依赖链计算完整影响范围，并要求问题与方法双向登记；`blocking = false` 的 P1/P2 只保留在 `UPSTREAM_ISSUES.json`，不写入方法的 `upstream_issue_ids`，也不冻结执行主路。禁止预填不存在的方法名。

连续编号的规则系列在进入生产前，必须先列出完整的 `evidence_atom_id` 集合并逐项对账。任何排除项只有在 `UPSTREAM_ISSUES.json` 中存在同一原文编号且 `blocking = true` 时，才允许标记为“上游阻塞”；否则不得漏读、排除或自行贴上游阻塞标签。

### 3.1 问题严重度和主线处理

所有上游和流水线问题按“会不会污染后面结果”分级，不按展示是否好看分级：

- **P0 致命级**：会破坏原文身份、边界、编号、页码、公式、核心条件、状态闸门或数据闭环，可能让下游读错、漏读或错误放行。对受影响的书包和下游主线立即停机；`UPSTREAM_ISSUES.json`必须写 `blocking = true`，正式书包或方法不得继续交付。
- **P1 观察级**：局部排版、单个不影响语义的错字或边缘展示问题。写入现有问题报告或缺陷记录，保持 `status = open`、`blocking = false`，不打断没有受到影响的主线；不能从记录里删除或静默改成“已解决”。
- **P2 观察级**：低影响的小瑕疵。和 P1 一样记账、留在待办中，主线继续；集中处理时如果发现它实际影响了原文意义或机器判断，必须升级为 P0，并重新检查受影响产物。

机器字段的统一对应关系是：`blocking = true` 代表 P0，`blocking = false` 代表 P1/P2；具体是 P1 还是 P2 写在问题类型和影响说明里。上游健康报告里的 `errors` 属于 P0，`review_candidates` 属于 P1/P2。P1/P2 不能覆盖 P0，也不能用“先继续跑”绕过 P0。

## 4. 整书知识地图合同

知识地图阶段（v2 起由本技能第 2 步执行，见 references/knowledge-map.md；原 book-to-skill 冻结原文原子模式）只生成：

```text
references/knowledge/
├── chapter-map.json
├── topic-map.json
└── glossary.json
```

每条地图记录必须带 `evidence_atom_ids（原文原子编号列表）`。可以保存页码、固定引用、标题路径和内容身份，但不能复制第二套完整原文，也不能决定判断方法。

章节摘要、主题标签和术语解释只用于导航，不是正式证据。

## 5. 判断方法合同

一个方法解决一种完整判断目标；一个步骤只执行一次明确检查。每个方法至少包含：

```text
method
title
generalization_scope
pilot_only
publishable
workflow_status
workflow_history
source_status
fact_binding_status
upstream_issue_ids
user_intents
required_facts
conditional_facts
dependencies
steps
retrieval_plan
stop_conditions
executable_in_pilot
```

`upstream_issue_ids`只能列开放且 `blocking = true` 的 P0 问题；P1/P2（`blocking = false`）只在 `UPSTREAM_ISSUES.json` 保留 `affected_method_ids`，不得写进方法字段或影响执行许可。

每个有原文支持的步骤至少包含：

```text
step_id
action
applicability_scope
minimum_supported_claim
produced_fact_keys
required_fact_keys
condition_logic
conditional_fact_requirements
source_status
evidence_refs
stop_condition
stop_fact_keys
exception_relations
forbidden_extensions
```

只针对某一个宫主或宫位的方法还必须在方法层声明 `target_house（固定目标宫位）`，取值只能是 1～12。JH8 事实转换时的实际目标宫位与它不一致，就必须拒绝生成判断请求；不能只靠调用者记住把方法编号和宫位参数配对。

`produced_fact_keys`必须是字符串数组，表示本步骤新产生、可供后续步骤使用的事实。它不能与本步骤的`required_fact_keys`、任何条件组的输入或方法的`required_facts`、`conditional_facts`重叠；同一方法内不能重复生产同一个事实。后续步骤只能使用已经完成的前序步骤产出，不能使用本步骤或未来步骤的产出。

`conditional_fact_requirements`是可选数组。每项必须包含：

```text
when：AND／OR／NOT 条件树
required_fact_keys：该分支选中后才必须取得的事实数组
stop_condition：缺少该分支事实时的具体停止说明
```

`when`只能引用本步骤的`required_fact_keys`或前序步骤产出，用来选择分支；条件组事实不能反过来决定自己是否被选择。条件组的`required_fact_keys`只能来自方法声明的`conditional_facts`或前序步骤产出，不能是本步骤或未来步骤的产出，也不能重复本步骤的 always-required 输入。`condition_logic`可以引用本步骤 always-required 输入、已声明的条件组输入和前序产出，但不能引用本步骤或未来步骤产出。

每条 `evidence_refs（步骤证据列表）`必须保存：

```text
evidence_atom_id
quote
pdf_pages
```

`quote（逐字短引）`必须原样存在于对应原文原子的 `exact_text（不得改字的原文）`中；页码必须完全一致。

`stop_fact_keys（缺失即停字段）`必须与本步骤的 `required_fact_keys（步骤所需事实）`完全一致；`condition_logic（条件关系）`只能使用 `AND`、`OR`、`NOT`，并且必须覆盖本步骤所需事实，同时只能引用当前可用的输入、条件组输入和前序产出。每个条件组的`when`必须能够由当前可用事实选择，不能引用未声明、当前产出或未来产出。适用范围、原文直接支持的最小意思和禁止扩大说明不得为空；例外、取消、缓解或限制关系必须逐条挂原文编号，找不到时不能自行补写。

当前方法步骤只接受 `content_role（正文身份）`为 `verse（正文偈文）`、`prose（正文论述）`或`table（正文表格）`的原文原子。`intro（导言）`、`note（译注或补充）`、`case（完整案例正文）`、举例、译者心得和编辑意见只能保留为辅助材料，不能进入通用方法步骤的 `evidence_refs（步骤证据列表）`。案例里的星盘附件也不能单独升级为通用规则证据。遇到新的正文身份时先停止并登记，不得猜测放行。步骤的原文编号、逐字短引、非空 PDF 页码和非空停止条件缺一即失败。

允许的来源状态：

```text
repeated_support
single_explicit_source
structure_hint_only
synthesized_candidate
no_source_in_scope
```

只有前两种来源状态在完成核验后可以进入执行主路。`repeated_support（多处重复支持）`必须至少来自两个不同的原文编号，不能把同一原文拆成两条短引凑数；单一明确来源可以保留为 `single_explicit_source`。方法没有逐步骤证据时必须设置 `executable_in_pilot = false`。

`fact_binding_status（排盘事实接入状态）`只能为：

```text
unmapped
mapped
unavailable
```

只有 `mapped（已接入）`可以进入执行主路。步骤使用的每个事实都必须先出现在方法的必查或条件事实中。依赖方法必须存在、不得循环；开放执行的方法只能依赖同样允许执行的方法。未解决且阻塞的上游问题必须阻止受影响方法执行。

运行时不得把“字段可用性”和“原文条件真假”混成一个状态。排盘事实先记录 `known／unknown／unavailable／not_applicable`；原文条件再记录 `satisfied／not_satisfied／unknown`。空数组、数字 0 和布尔值 false 都是已取得的值，不能因为是假值而当成缺失。

判断代理只能接收事实转换脚本生成的 `judgment_request（允许判断的请求对象）`。任一必查事实不是已取得或明确不适用、方法尚未接通、方法未获执行许可、依赖方法未获许可或仍有上游问题时，必须设置 `judgment_allowed = false`、`judgment_request = null`，并只输出已确认事实、缺失关键事实、停止原因和禁止输出的结论。完整事实底账只用于检查，不能绕过闸门直接交给判断代理。

## 6. 判断导航合同

两份机器真相固定为：

```text
references/navigation/method-recipes.json
references/navigation/query-recipes.json
```

- 方法、步骤、事实、依赖、证据、状态和执行许可只写在 `method-recipes.json`。
- 主题、方法路由、必查事实、四路查询和停止条件只写在 `query-recipes.json`。
- 主题可以引用方法编号，不得复制方法步骤。

以下文件全部是派生展示：

```text
references/navigation/
├── method-map.md
├── required-checks.json
├── version-routing.md
└── topics/*.md
methods/families/*.md
methods/verified.md
UPSTREAM_ISSUES.md
```

每个主题必须包含：

```text
title
user_intents
method_ids
candidate_method_ids
required_facts
conditional_facts
fact_binding_status
support_queries
counter_queries
boundary_queries
method_queries
stop_conditions
execution_allowed
```

四路查询含义：

- `support_queries`：寻找直接支持；
- `counter_queries`：寻找相反、取消或缓解；
- `boundary_queries`：寻找成立条件、文本身份和适用边界；
- `method_queries`：寻找作者要求怎样判断。

每条查询保持单一目的。查询词、方法摘要和主题说明都不是证据。

`method_ids（可执行方法编号）`只能引用 `executable_in_pilot = true`的方法。尚未完成独立核验的方法可以放入 `candidate_method_ids（候选方法编号）`帮助测试字段和查询计划，但此时必须设置 `execution_allowed = false`，不得交给判断代理实际执行。

运行 `validate_delivery.py --render-derived <目标目录>`生成派生文件。任何派生文件被手改后，普通机械验收必须失败；不得靠关键词表猜人读文件是否越权。

`validation/method-source-scan.json（全书方法审查清单）`是另一份必须验收的总账。它必须对工作单允许范围内的每个 `evidence_atom_id`记录一个且只有一个最终去向；`review_pending（尚未审查）`不能通过。知识地图全量覆盖只证明原文有位置，不能代替方法语义审查。方法步骤实际引用的原文编号必须在此清单中标为 `method_step`，并列出实际引用它的方法。

在正式全书蒸馏中，这份清单还必须把“原文是什么”和“现在怎么处理”分开：

```text
semantic_class：原文实际类型
disposition：处理去向
risk_flags：前后文依赖、正文夹译注、残缺条件、取消条款、时间限制等风险
```

`semantic_class`至少允许 `judgment_method`、`condition_result`、`exception_boundary`、`calculation_rule`、`foundational_knowledge`、`case_or_commentary`和`unresolved_source`。一个原文只能有一个最终处理去向，但可以被多个方法引用。存在开放阻塞问题时，即使其文字看起来包含方法或规则，也必须保留风险和阻塞关系，不能靠改分类把问题洗白。

分类阶段允许使用 `method_candidate（方法候选）`作为处理中间去向：它表示这条原文已经确认包含可生产的方法或规则，但尚未生成方法配方。它不得填写 `method_ids`，不得进入执行主路，也不得通过正式交付。方法生产后必须改成有真实步骤引用的 `method_step`，或明确改成 `reviewed_no_method`；这样才能避免“必须先清空待审查才能写方法，但不写方法又无法清空待审查”的循环。

全书批量分类前必须先用跨章节难例校准分类口径；每章完成后必须反向检查本章是否漏掉判断顺序、成立条件、取消条件、边界和时间限制。校准样品和分类结果只属于蒸馏候选，不能作为正式证据或独立核验凭证。

### 6.1 A 类正式方法怎样分批生产

A 类的稳定偈号、条目号或组合编号只帮助定位，不能代替逐字原文证据。批量生产固定按以下顺序：

1. 先完成整书知识地图和全量分类总账；`review_pending（尚未审查）`必须为 0，方法候选、资料、案例和阻塞项的编号集合必须与正式原子集合完全对齐。
2. 先做 10 个跨章节高风险样品，至少覆盖章节大前提、AND／OR 分支、取消与缓解、分盘范围、时间范围、译注混入和缺事实停判。样品只校准模具，不能替后续批次免检。
3. 样品通过后按专题块生产。一个批次通常覆盖 40～120 个审查步骤，或一个完整专题；不得按单条原文拆批。一个专题不足 40 步时，按直接依赖并入相邻专题。开工时锁定本批原文编号集合和关联的例外／边界来源，完成前不换输入。
4. 每批只在同一份 `method-recipes.json（方法机器配方）`和 `query-recipes.json（主题查询配方）`中追加机器真相，并同步把已使用来源从 `method_candidate（方法候选）`改为有真实方法编号的 `method_step（已进入方法步骤）`。人读文件仍由验证器生成。
5. 每批必须独立完成：交付验证、正确／已知错误／空白三对照，以及对生成报告 `audit_step_ids（机器指定的审查步骤）`做独立语义检查。全审批次覆盖全部步骤；符合抽查条件的简单落宫批次只检查机器固定抽出的 20%。任何一步失败，只退回本批及其真实依赖；已闭环且不依赖问题来源的旧批次不重做。驳回后必须新建目录：未被驳回的结构化步骤可以原样搬入，只重写被驳回步骤，再由唯一生成器整体重建，不得把旧机器文件和旧审查结论直接当新结果。
6. 新批次只允许本技能 `scripts/build_methods.py`（v2 升级后唯一入口，原 cangjie-skill 同名脚本已随拆网定案 Q19 搬入）生成。大运流年、多星同聚和复杂瑜伽强制逐步全审；生产连续不等于审计降级，只有结构单一的落宫章节连续三个批次独立全审且没有出现新的错误家族后才允许按批次名固定抽取 20% 步骤审查，一次性内容失误只退回本批；每三个高速批次仍全审一个批次。

提效只发生在确定性工作：编号集合对账、字段完整、逐字短引、页码、重复项、退役字段、状态和派生文件一致性都交给脚本。人工智能集中处理原文类型、最小支持意思、条件分支、取消／缓解关系和禁止扩大解释。正则初筛只能标记可疑点，不能自动决定语义分类或把未命中项视为安全。

独立语义检查只控制本批能否并入全书，不控制无依赖批次能否继续生产。等待检查时，下一批可以继续生成、跑 v2 交付检查和三类检查；任何未完成独立检查的批次都不得提前写入全书总账。审计报告提前完成时先落盘，主窗口在当前批次机器检查完成后的批次交界点再读取和处理。当前审计保持全审，连续三个批次全审且没有出现新的错误家族后才允许简单落宫批次抽审，一次性内容失误只退回本批。

合同中的停产条件只有三类：包级 P0、会污染当前批次的验证器假通过、下一批确实依赖被拒原文。没有可并入的绿批次本身不是停产条件；生产通道仍可继续，合并通道只接收独立检查完成的批次。

格式、字段、逐字引文、页码、分支通电、占位事实、固定抽样和状态跳级属于机器职责，不再让独立人工智能逐批重复判断。共享程序和验证器保持冻结；代码审计发现的洞，必须先证明某个真实批次因此被错误放行或错误拦下，并交付批次路径、命令、预期结果、实际结果和影响范围，否则只登记到“本门不查什么”，不修、不停产。同一语义错误家族第二次出现时，禁止继续修单批文件；必须回到共享生成规则或验证器，并至少保留一组能通过的正确样本和一组会被拒绝的错误样本。共享程序真正解冻时，独立审计必须一次检查两分支、三分支、跨分支借条件、完整原文与短引，以及 `A or B`、`Either … or`、`or if/when/in`，不允许一洞一修。

### 6.2 通用内核、每书工作单和策略微调

A 类和 B 类共用同一个生产内核：只读验收后的原文原子；机器搬运 `evidence_atom_id`、逐字短引和 PDF 页码；人工智能只判断原文最小意思、成立逻辑、取消／缓解关系和缺事实停判。每个方法步骤都必须单独绑定这三项证据，不能用方法级宽泛引文替代。

每本书的 `WORK_ORDER.json`必须另行写清书籍版本、A 类或 B 类、允许范围、专题顺序、当前批次和验收要求。工作单只配置本书，不能放宽通用证据、状态或执行闸门；本书策略只能调整分组、顺序和批次边界。

- A 类按稳定编号组织同型的连续规则系列；偈号或条目号只用于锁定范围，不能代替原文证据。
- B 类按语义连续块、表格边界和案例边界组织专题；没有稳定偈号时不得硬套 A 类偈号，也不得把表格或案例边界强行改造成偈文规则。

JH8 或 RAG 的字段缺口不阻止候选整理和方法生产，但一律阻止执行；事实未接通的方法必须保持 `executable_in_pilot = false`。普通内容批次只做交付验证、真实正常／错误／空白三对照和本批独立语义检查；只有验证器发生改动时才额外跑验证器自测。

若新发现的验证器假通过会影响当前批次，本批考试无效，先修闸门再重新考试；只有明确属于当前闸门职责之外且不影响本批的边界问题，才可登记边界后继续。P1/P2（`blocking = false`）继续记账；原子级 P0 只隔离实际引用该原子的批次、方法和依赖，不连坐无关内容；包级 P0 仍整本书停止。已闭环批次只有在原文或共享规则确实影响它时才重检，一批失败只退回本批和真实依赖。

每批结束时按机器记录修正状态数字，不沿用估算数。合并脚本成功后必须把新增方法数、消化原文数和合并后剩余候选数自动写入整书 `PIPELINE_STATE.md`，重启只读状态文件。批次报告只报告方法数、步骤数、已消化候选数、剩余候选数和机器记录路径；批大小以机器指定的审查步骤能够一次检查完成为上限。

## 7. 状态合同

试验状态：

```text
pilot_candidate
→ mechanical_verified
→ independent_verified
→ shadow_passed
→ pilot_passed
```

任何阶段可以进入 `blocked`或`rejected`。生成窗口只能生成候选并完成机械核验，不能给自己标记独立核验或 Shadow（独立影子考试区）通过。

进入 `independent_verified（独立核验完成）`或更后状态时，必须存在绑定同一原文内容摘要和本次蒸馏运行、且运行编号不同的独立核验凭证。凭证还必须绑定当前 `method-recipes.json（方法机器配方）`的准确内容摘要，并列出本批生成报告 `audit_step_ids（机器指定的审查步骤）`中的全部步骤编号；全审时该清单就是本批全部步骤，抽查时就是机器固定抽出的 20%。方法配方、机器审查清单或被审步骤有任何改动，旧凭证立即失效。进入 Shadow 或试验通过还必须分别提供对应凭证。机器只能核对凭证绑定和运行记录不同，最终人工批准仍由人负责。

`PILOT_STATUS.json（试验状态文件）`拥有更高的执行否决权：`independent_verification_allowed = false`时，任何方法不得进入独立核验及以后状态；`shadow_allowed = false`时不得进入 Shadow 及以后状态；`forbidden_uses`包含`production_agent_execution`时，可执行方法必须为 0，所有主题的`execution_allowed`必须为 false。格式正确的核验凭证不能覆盖这些禁令。

试验状态不能转换成正式发布状态。正式已验收书包完成后必须从知识地图开始全部重跑。

## 8. 断点续跑合同

1. 开工先读 `WORK_ORDER.json`和`PIPELINE_STATE.md`。
2. 状态写完成但产物不存在时，标记状态漂移，只重做该阶段。
3. 每完成一个阶段立即更新真实产物、数量、失败和唯一下一步。
4. 状态文件只保存进度，不保存书摘、方法正文或判断结论。
5. 每次蒸馏目录必须有 `DISTILLATION_SOURCE.json`，绑定本次运行、书籍、版本、源文件身份、实际输入路径、原文内容摘要和读取范围。

## 9. 机械验收合同

`validate_delivery.py（交付核验脚本）`必须检查：

1. 固定目录和文件存在；
2. 所有机器文件的试验和发布标记正确；
3. 方法人读文件与方法机器配方逐字一致；
4. 主题人读文件和必查清单与主题机器配方逐字一致；
5. 四路查询均为非空数组；
6. 所有步骤原文编号存在且在允许范围；
7. 逐字短引和 PDF 页码与冻结原文原子一致；
8. 阻塞或缺证据方法没有进入执行主路；
9. 新产物没有退役字段；
10. 输入原文原子内容摘要与锁定输入一致；试验模式还检查大小和最后修改时间。
11. 知识地图中的每一个原文编号真实存在且位于允许范围；
12. `workflow_history（状态变化记录）`从候选开始、逐级变化，并与当前状态一致；
13. 所有人读派生文件均与机器真相一致；
14. 每个有内容的步骤都有自己的来源状态。
15. 方法依赖存在且无循环，步骤事实全部已声明；
16. 排盘事实未接通、依赖不可执行或上游问题阻塞时不得执行；
17. 状态需要的独立核验、Shadow 和人工批准凭证存在并绑定当前输入；
18. 正式模式拒绝裸原文原子路径和任何 `PILOT_TEMP`输入。
19. 试验状态文件中的禁止项真实约束方法状态、可执行方法和主题执行许可；
20. 外层反假绿入口亲自运行正常、已知错误和空白三份对照，并从退出码和验证器 JSON 自动生成`controls（对照结果）`；
21. `run_receipt（机器运行凭证）`真实存在、可解析，并且其中三次运行结果与闸门报告的对照结果和数量一致。
22. 通用方法步骤不得引用导言、译注、案例、举例或编辑意见；每一步的证据三件套和停止条件必须非空。
23. 章节地图必须逐编号覆盖允许范围且无重复，不能只比总数。
24. 全书方法审查清单必须逐编号给出最终去向，不能把关键词候选扫描当成语义审查。
25. 步骤的字段刹车、`AND／OR／NOT`条件关系、适用范围、最小支持意思、例外关系和禁止扩大说明必须完整。
26. 方法声明的必查事实必须真的被步骤使用；`repeated_support`必须由至少两个不同的原文编号支持。
27. 上游问题的影响范围必须由实际证据引用和方法依赖自动反查；蒸馏窗口不能自行把上游问题改为已解决。
28. 独立核验凭证必须绑定当前方法配方内容和机器指定的全部审查步骤，不能只绑定书籍摘要和方法编号，也不能人工替换抽查名单。
29. v2 配方的每个 `selection_group（可选分支组）`必须运行三组单分支仿真：只满足一个分支时放行、全部不满足时停止、已经满足一个分支时不得被未选分支的缺失事实误停。
30. `minimum_supported_claim（原文最小意思）`不得命中空话黑名单；同一批次至少三个步骤复读同一句空话时失败。生成器还必须保存并核对条件词、结果词在逐字短引和最小意思中的对应关系。`required_fact_keys`、`produced_fact_keys`和条件组事实命中 `source_*`、`choice_*`、"原文事实已取得"、"或者分支 A/B"或"条件已成立"等占位模式时，生成器和验证器都必须失败。

机械验收只使用这一份验证器，不增加第二套验证逻辑、兼容路径或重复事实源。外层反假绿入口只负责运行同一验证器并核对真实进程结果。原文内容摘要检查是已复现篡改风险后的必要闸门。

v2 批次状态只能按“未开工→生成中→机检仿真→审计中→已并入”单向前进。机器检查失败或独立审计出现 REJECT 时，本批必须进入 `rejected（本批失败，已经结束）`；失败目录只保留证据，不得原地修补或重跑，新尝试必须使用新目录。`advance_batch_state.py`只有在 v2 交付检查和正确／错误／空白三类检查全部符合预期后才能进入审计中；`merge_method_batch.py`只有在独立审计覆盖机器指定步骤且全部为 PASS 后才能并入，并入前必须创建时间戳备份并核对新增方法数、消化原文数和剩余候选数；合并成功后自动把三个数写入整书 `PIPELINE_STATE.md`。

## 10. 完工和交接

本窗口完成机械验收后，把以下内容交给独立核验窗口：

- 已验收书包或试验夹具身份、原文原子路径、内容摘要和读取范围；
- 知识地图；
- 方法候选和逐步骤证据；
- 判断导航配方；
- 机械验收报告；
- 外层三对照机器运行凭证和闸门报告；
- 上游问题、排盘事实接入状态和待锚定项目。

没有独立核验结果时，状态必须停在 `mechanical_verified（机械核验完成）`或更早阶段。试验完成也不能安装到正式运行环境。

## 11. 多本书独立生产与组合查询

### 11.1 每本书必须单独生产

一次正式运行只读取一本书、一个版本对应的 `accepted-package.json（已验收书包凭证）`。每本书分别生成自己的知识地图、方法配方、主题配方、检查记录和问题清单，禁止把两本书的原文原子写进同一个单书目录。

跨书引用方法时，身份必须同时包含：

```text
book_id
edition_id
method
```

不能只凭 `method（方法编号）`跨书定位，避免两本书出现同名方法后互相覆盖。

### 11.2 书单岗位不是证据

选书方案可以预先写明一本书计划负责什么，但计划岗位不能自动进入正式调用。一本书至少要依次完成：

```text
知识地图和方法候选生成
→ 机械检查通过
→ 由没有参与制作的人工智能检查问题
→ 实际问题考试通过
→ 用户批准
→ 允许正式调用该书岗位
```

机械检查通过只允许进入下一项检查，不能单独开放正式调用。

### 11.3 第一批两本书的固定决定

- BPHS 只正式加工 97 章版；100 章版以后作为独立版本处理，两版原文和引用永不混写。
- BPHS 97 计划承担古典根本断语来源；UK（《乌塔拉·卡拉姆里塔》）计划承担宫位、行星和事物表征清单来源。
- 哪本书的正式书包先到，就先独立加工哪本，不等待另一册。
- 每个方法批次只运行当前书包的权威健康检查；项目总检查可以报告其他书失败，但其他书的 P0 不阻塞这本已经单独通过的书。
- 两本书都获准正式调用后，才允许建立同时查询 BPHS 97 和 UK 的共同路线。

UK 全书仍要建立知识地图。与本命判断无关的择日、问卜或仪轨内容只能标记为不进入本命判断路线，不能从原文库删除或假装不存在。

### 11.4 组合查询只做路由，不合并证据

共同查询路线只能引用已经允许正式调用的单书方法，不复制方法步骤，也不生成第三份改写原文。回答必须分开显示：

```text
BPHS 97 依据
UK 依据
两书差异或冲突
当前事实满足、未满足和未知
仍然不能确认的部分
```

禁止把两书内容压成“古籍认为”。其中一本尚未获准正式调用时，可以继续运行另一册的单书路线，但必须明确写出缺少哪一本；需要两本共同支持的路线必须停止。

PVR（整盘步骤教材）、300C（300 个组合规则书）和 K.N. Rao（时间判断教材）尚未完成正式加工时，只保留未来接入位置，不得让人工智能补出完整看盘顺序、组合规则或时间方法。

### 11.5 当前实现边界

现有验证器已经能检查单书试验产物和单书正式候选，但尚未实现正式多书岗位开放和共同查询路线的机器检查。未补齐时可以继续各书独立生产、独立检查和独立考试，不能宣布多书共同路线已经可用。
