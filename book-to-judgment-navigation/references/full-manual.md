每完成一步立即更新 `PIPELINE_STATE.md`，只记录真实产物、失败、数量和唯一下一步。

### A 类批量提效

A 类（原书有稳定编号）不另建一套工具。整书地图和全书分类总账只做一次；10 个高风险样品把模具跑通后，剩余方法按专题块依次生产。每批都要锁定原文编号集合、关联例外和依赖，完成机器配方、派生文件重生、交付验证和三对照后即可送独立语义检查；等待独立检查时，无依赖的下一批可以继续生产和机器检查。审计子任务提前完成时只把报告落盘，主窗口在当前批次机器检查完成前不读取、不处理审计消息；到批次交界点再统一处理。生产节奏与审计密度分开：当前审计保持全审，连续三个批次全审且没有出现新的错误家族后，才允许简单落宫批次抽审；零星的一次性内容失误只退回本批，不重置这项计数。只有独立检查完成的批次才能更新全书方法总账并并入。

大运流年、多星同聚、复杂瑜伽和任何新书型首批强制逐步全审。只有结构单一的落宫章节连续三个批次没有出现新的错误家族后，才允许进入机器固定抽审；每三个高速批次仍有一个全审批次，抽中新的错误家族时立即把当前批次和相邻批次恢复全审。

批次大小以“机器为本批指定的审查步骤能够一次检查完成”为上限，也有下限：通常一次覆盖 40～120 个审查步骤，或一个完整专题；不得按单条原文拆成一批。若一个专题本身少于 40 步，按直接依赖把相邻专题并入同一批。全审批次检查全部步骤；符合抽查条件的简单落宫批次只检查机器固定抽出的 20%。机械初筛可以一次扫全书，但只生成风险候选；不能替人工智能完成语义分类，也不能把没有命中关键词的原文自动放行。

### 通用内核、每书工作单和策略微调

以后 A 类和 B 类都使用同一个通用内核：只读已验收的原文原子，机器负责搬运原文编号、逐字短引和 PDF 页码，人工智能只判断原文的最小意思、条件逻辑、取消／缓解关系和缺事实停判；方法步骤仍必须逐条绑定证据三件套。

每本书的 `WORK_ORDER.json（本书工作单）`另外写清书籍版本、A 类或 B 类、允许范围、专题顺序、当前批次和验收要求。工作单是本书的配置，不改变通用内核；本书的策略只能调整分组和顺序，不能放宽证据、状态或执行闸门。

- A 类按稳定编号组织同型的连续规则系列，可以按偈号或条目号锁定批次，但编号不能代替原文证据。
- B 类按语义连续块、表格边界和案例边界组织专题；B 类没有稳定偈号时，不得硬套 A 类编号或把表格／案例切成偈号规则。

JH8（排盘事实系统）或 RAG（原文检索系统）暂时缺字段，只阻止执行，不阻止候选整理和方法生产；方法在事实未接通时必须保持 `executable_in_pilot = false`，不能为了推进批次把缺口写成已满足。

普通内容批次只跑交付验证、真实正常／错误／空白三对照和本批独立语义检查；只有修改验证器时才跑验证器自测。若新发现的验证器假通过会影响当前批次，本批考试立即作废，先修闸门再重考；只有明确属于当前闸门职责之外且不影响本批的边界问题，才能登记后继续。

P1/P2（`blocking = false`）继续记账；原子级 P0 只隔离真正引用该原子的批次、方法和依赖，不连坐无关内容；包级 P0 仍然整本书停止。已闭环批次只有在原文或共享规则实际影响它时才重检；某批失败只退回本批和真实依赖。

每批完成后按机器记录修正状态数字，不沿用估算数。`merge_method_batch.py（单批合入脚本）`成功时必须自动把本批新增方法数、消化原文数和合并后剩余候选数写入整书 `PIPELINE_STATE.md（整书进度文件）`；重启后只读该文件，不依赖聊天记忆。批次报告只写方法数、步骤数、已消化候选数、剩余候选数和机器记录路径；批大小继续以一次独立语义检查能够完成为上限。

### 批次怎样推进，怎样避免重复返工

单批机器状态只按 `not_started（未开工）→ generating（正在生成）→ mechanical_testing（机器检查）→ audit_in_progress（独立检查）→ merged（已并入）`前进。机器检查失败或独立检查发现问题时，当前状态必须进入 `rejected（本批失败，已经结束）`，旧目录只保留证据，禁止在原目录继续修改或重跑；重新生产必须新建目录。`build_methods.py（唯一方法生成脚本）`创建前三个状态，`advance_batch_state.py（送独立检查脚本）`只在 v2 交付检查和三类检查都符合预期后进入独立检查，`merge_method_batch.py（单批合入脚本）`只在独立检查覆盖机器指定步骤且本轮未找到问题后并入。

机器检查失败只退回本批。独立检查发现问题只退回本批和真实依赖；没有依赖的下一批照常生产，但不得提前并入。重新生产必须新建目录：旧目录只留运行记录；没有被驳回的步骤，从旧批次的结构化抽取中原样搬入新目录，只重写被驳回步骤，再由 `build_methods.py` 整体重建机器文件、派生文件、三类对照和状态。禁止直接复制旧 `method-recipes.json` 或把旧审查结论当成新结论。包级 P0 才停止整本书；原子级 P0 只隔离真实引用该原子的内容。

“当前没有绿批次可合并”不是停产条件。正式书包健康、共享程序没有待修、下一批不依赖被拒原文或失效闸门时，生产和机器检查继续；审计只控制本批何时能合并，拒绝批次单独重跑。

格式、字段、逐字短引、页码、分支通电、占位事实、固定抽样和状态跳级都由机器判断，独立人工智能不重复检查。共享生成程序和验证器保持冻结；代码审计发现的疑似漏洞，只有拿出真实批次路径、实际命令、预期结果和实际结果，证明它已经错误放行或错误拦截，才允许解冻修复。没有真实批次证据的漏洞只登记到生成规则登记簿的“本门不查什么”，不改闸门、不停产。已确认有真实失败证据的失败终态、合入原子性、备份目录污染和派生文件回滚继续保留。若同一语义错误家族再次出现，停止逐批修补，先改共享生成规则或验证器，并留下正反回归样本；旧批次只有真实引用了受影响规则或原文时才重检。共享程序真正解冻时，独立检查必须一次覆盖完整 OR 组合矩阵，不按单个漏洞逐轮解冻。

不创建 `audit-queue.md` 或其他第二套队列。项目当前数字以 `JUDGMENT_PIPELINE_STATUS.json（判断导航当前状态总账）`为准；单批只认 `validation/batch-state.json（单批机器状态）`和真实运行凭证。

## 输入边界

- 不读取 PDF、`book.md`或`pages.jsonl`补证据。
- 不修改、合并、拆分、改写、修复或重新编号原文原子。
- 发现原文原子问题时写入目标目录的 `UPSTREAM_ISSUES.json（上游问题机器记录）`并报告主窗口；`UPSTREAM_ISSUES.md（人读展示）`只能由验证器生成。
- 上游问题按合同分级：会污染原文、条件、公式、状态或方向的 P0 必须写 `blocking=true` 并停止受影响主线；P1/P2 只写入现有问题记录、保持 `status=open` 和 `blocking=false`，不打断无关主线，后来发现影响意义时升级为 P0。
- 试验范围外的原文内容不得进入蒸馏结果。
- 原文锚点只能使用 `evidence_atom_id（原文原子编号）`或`evidence_atom_ids（原文原子编号列表）`；`work_id`、`parent_id`、`card_id`、`source_atom_ids`、`filters.work_ids`和`contract_v2.1`均为退役词，禁止进入新产物。
- 方法步骤证据只能引用被认定为正文的原文原子；导言、译注、案例、举例和编辑意见只能保留辅助身份，不能给通用判断步骤背书。每个步骤的原文编号、逐字短引、非空 PDF 页码和非空停止条件缺一即失败。每个步骤还必须声明`produced_fact_keys（本步骤产出事实）`；可选的`conditional_fact_requirements（按分支必查事实）`必须写明选择条件、分支事实和具体停止条件。步骤不能使用自己或未来步骤产出的事实，也不能重复产出。
- 正式模式拒绝裸原文原子路径；试验模式拒绝任何允许发布、迁移或生产执行的状态。
- 正式书包实时检查失败时先分流：若是内容、身份、边界、编号或摘要不一致，停止受影响书的全部证据工作；若上游已经证明只是登记记录缺失，只允许做不绑定正式原文编号的候选整理、考题和接口联调，禁止生成正式方法配方、逐字短引和可发布文件。正式书包重新通过后必须重新读取新版原文并从零绑定 `evidence_atom_id`。
- 正式书包还必须由上游证明原页结构已经逐页反查：每页表格数量都有人工依据，原页候选和已登记结构双向对账，续表指向真实表格块，已登记表格内容没有损坏。蒸馏窗口只检查上游凭证和真实退出码，不回看 PDF 代做这项工作。

## 三个工具的边界

- `book-to-skill（整书知识地图工具）`只回答“书里有什么、在哪里”。
- `Cangjie（判断方法蒸馏工具）`只回答“这类问题应检查什么、按什么顺序、缺什么必须停”。
- 本 Skill 只回答“当前问题应选择哪些已核验方法并怎样生成查书计划”。
- RAG（原文证据检索系统）负责重新取回真实原文；判断代理负责核对当前事实是否满足原文条件。

## JH8 排盘事实接入

使用 `scripts/adapt_jh8_facts.py（JH8 事实转换脚本）`把 JH8 已经算好的正式事实整理为方法配方使用的中文事实。该脚本只读取 `02_命盘轻量包.json`、`资料柜/细节包.json`和`资料柜/命盘闭环验收.json`，不重新计算命盘、相位、六力或运期。

```bash
python scripts/adapt_jh8_facts.py <JH8命盘目录> \
  --target-house 7 \
  --as-of 2026-08-16 \
  --recipes <目标目录>/references/navigation/method-recipes.json \
  --output <目标目录>/validation/jh8-field-test/正确样本输出.json
```

JH8 没有正式交付的字段必须输出 `unavailable（无法取得）`并形成停止原因；来自用户问题或 RAG 的事实必须分别标记 `caller_required（等待用户问题分类）`或`method_or_rag_required（等待方法或原文）`。不能导入 PyJHora 或本机其他排盘工具补算缺口，也不能因为部分字段已接通就把方法的 `fact_binding_status（排盘事实接入状态）`改成 `mapped（已全部接通）`。

事实可用性和原文条件真假必须分开：排盘字段只记录 `known（已取得）／unknown（尚未取得）／unavailable（当前无法取得）／not_applicable（本方法不适用）`；只有拿到方法条件后，才能另行记录 `satisfied（满足）／not_satisfied（不满足）／unknown（无法判定）`。禁止把“字段已取得”写成“原文条件已满足”，也禁止把空数组、数字 0 或布尔值 false 当成缺失。

所有判断调用只能读取脚本输出的 `judgment_request（允许交给判断代理的唯一请求对象）`。`judgment_allowed = false`时，该字段必须为 null，只能把 `stop_output（停判输出）`交给回答层；不得把完整 `facts（事实检查底账）`直接喂给大模型绕过闸门。`stop_output`只包含已确认事实、缺失关键事实、停止原因和禁止输出的结论。检查字段时不选择 `--method`，脚本永远保持停判；准备调用具体方法时必须显式传入 `--method <方法编号>`。

## 试验与正式发布隔离

试验产物必须同时标记：

```text
pilot_only = true
publishable = false
artifact_scope = PILOT_TEMP
formal_migration = FORBIDDEN
```

`PILOT_STATUS.json（临时资产状态）`是试验隔离的唯一机器真相，也是执行否决权。它禁止独立核验、Shadow（独立影子考试）或生产执行时，方法状态、主题许可和任何核验凭证都不能越权；只有该文件明确允许的阶段才可继续。试验状态最多走到 `pilot_passed（试验通过）`，不能转换成正式发布。上游正式书包完成后，知识地图、方法候选、核验和考试全部重新运行；不做编号映射，也不直接沿用试验结论。

人读方法、主题文件、`required-checks.json（必查清单派生文件）`、方法地图、核验状态和上游问题说明都不是独立事实源；任一文件被手改后必须由机械验收判失败。

## 验收

正式批次先检查当前工作单绑定的这一份书包：

```bash
python -c "from pathlib import Path; from tools.register_accepted_package import run_authoritative_validation; run_authoritative_validation(Path(r'<当前工作单的 accepted_package_path>'))"
```

退出码为 0 后，才运行本批交付检查：

```bash
python scripts/validate_delivery.py <目标目录> --require-v2
```

机械验收至少检查：正式书包或试验状态合法、试验禁令真正否决状态和执行许可、原文内容摘要一致、来源清单绑定当前输入、章节地图逐编号全量覆盖且无重复、全书每条原文都有方法审查去向、步骤和知识地图原文编号存在、短引逐字匹配、页码一致、步骤适用范围与最小意思非空、`AND／OR／NOT` 条件关系合法、步骤产出唯一且不能被本步或未来步骤偷用、条件组的选择事实和分支事实均已声明、缺失即停字段与步骤事实一致、四路查询齐全、步骤事实已声明且必查事实真的被步骤使用、`repeated_support（多处重复支持）`具有至少两个独立原文编号、方法依赖存在且无循环、坏原文按实际引用和依赖自动冻结、排盘事实已接通、上游问题已登记且未被蒸馏窗口私自标记解决、状态没有跳级、所需独立核验凭证绑定当前方法配方内容和机器指定的审查步骤、人读派生文件与机器真相逐字一致、阻塞方法没有进入执行主路、退役字段未进入新产物。外层验收还必须证明正常夹具退出码为 0 且执行数为 0、错误夹具和空白基线退出码非 0，并保存可解析的真实机器运行凭证。
机械验收还必须区分问题严重度：P0（`blocking=true`）直接使受影响交付失败；P1/P2（`blocking=false`）必须保留在问题记录中，但不能单独把没有受影响的主线判失败。

## 禁止事项

- 不重切书，不重做 OCR，不重建或修改 RAG 索引。
- 不从用户问题反向编造书中方法。
- 不把摘要、案例、目录、查询词或方法解释当正式证据。
- 不让生成窗口完成自己的独立核验。
- 不接受人工填写的对照结论、无法读取的运行凭证或只凭报告自报字段形成的“通过”。
- 不建立兼容模式、旧字段映射、双读或双写路径。
- 不把试验小样冒充整书覆盖或正式判断导航。
- 不把临时编号、方法、独立核验或考试结论迁移到正式书包；正式输入到位后只允许从零重跑。
