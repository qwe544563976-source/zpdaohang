# 事实键命名规范

> 事实键是交给排盘系统（JH8）的接口名。第一批 181 个键里只有 9 个被两个以上方法复用，
> 同一件事被写成好几个名字，等于同一个前置计算要算很多遍，JH8 对接时还得写一堆别名映射。
> 批量前定死写法，2000 个方法才能共用一套接口。
>
> 本规范只管**输入事实**（`facts` 里声明的、进 `condition_logic` 或分支的）。
> 产出事实（`produced_fact_keys`）是这一步的结论标签，不受本规范约束。

## 三条铁律

1. **原子可取值**：事实名必须是排盘能直接回答的一件事。
   名字里出现「或／之一／任一／及其」一律被生成器拒绝——那是把判断混进了取值。
2. **梵文原名一律带上**，格式固定 `中文名（Romanized）`，第一次和第一百次都带。
   不带原名在跨书（BPHS／UK／300C）合并时无法对齐。
3. **同一件事只有一个名字**。下表有模板的按模板写，没有的先照最接近的模板套。

## 模板表

| 类型 | 模板 | 例 |
|---|---|---|
| 基座·主星身份 | `本盘{N}宫主是哪颗行星` | 本盘五宫主是哪颗行星 |
| 基座·落宫取值 | `本盘{N}宫主落在哪一宫` | 本盘五宫主落在哪一宫 |
| 基座·星座取值 | `本盘{N}宫（{梵文}）落在哪个星座` | 本盘三宫（Sahaj）落在哪个星座 |
| 基座·吉凶名册 | `本盘中哪些行星被判为吉星` / `…凶星` | （固定写法，不要再写「命盘中哪些行星为吉星」） |
| 落宫 | `{行星}（{梵文}）是否落{N}宫（{梵文}）` | 土星（Shani）是否落九宫（Dharm） |
| 尊贵状态 | `{行星}（{梵文}）是否入旺` / `是否落陷` / `是否落本宫` | 五宫主（Putr's Lord）是否入旺 |
| 深度尊贵 | `{行星}（{梵文}）是否深度入旺` | 木星（Guru）是否深度入旺 |

## 译名红线（生成器已硬拦）

| 英文 | 唯一正确中文 | 禁用 | 为什么 |
|---|---|---|---|
| exalted / exaltation | 入旺 | 庙、入庙、入庙旺 | 庙是本宫 own sign，旺是 exaltation，混用把触发面扩大一倍 |
| own sign | 本宫（庙） | 旺 | 同上，反向 |
| trine | 三角宫 | 三分宫、三分盘 | 三分盘是 Drekkana D3，只差一字 |
| Decanate / Drekkana | 三分盘（D3） | 十分盘、九分盘 | 写错分盘等于换一张盘 |
| Navamsa | 九分盘（D9） | 三分盘、十分盘 | 同上 |
| Dasamsa | 十分盘（D10） | 三分盘、九分盘 | 同上 |

## 结果动词红线（生成器已硬拦）

原文只说 `pass away` / `die` / `lose` 时，中文写「去世／失去／没有」。
**禁止**「夭亡／夭折／早夭／暴毙／绝嗣」——这些词自带年龄、死因或宗族含义，原文没给就不许补。

## 复用优先

写事实键前先查本批已有的键。能复用就复用，不要因为多加一个括号就变成新键。
第一批的三组真实反例（已在 run03 统一）：

```text
五宫主是否入旺            ← 与「五宫主（Putr's Lord）是否入旺」是同一件事
土星是否落九宫            ← 与「土星（Shani）是否落九宫（Dharm）」是同一件事
太阳（Surya）是否落四宫（Bandhu） ← 与「…（Bandhu Bhava）」是同一件事
```

按铁律 2，上面每组都取**带完整梵文原名**的那个写法。
